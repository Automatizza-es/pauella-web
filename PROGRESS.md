# Pauella — Progreso del proyecto

Rediseño completo de la web de Pauella (paella en directo para eventos en Los Ángeles). Este archivo resume qué se ha hecho, qué queda pendiente y qué ideas hay para más adelante. Se actualiza en cada sesión de trabajo.

## Stack

- Next.js 16 (App Router) + TypeScript + Tailwind v4, mismas convenciones que `automatizza-web` (src/app, alias `@/*`, ESLint flat config).
- Fuentes: **Newsreader** (serif editorial, titulares) + **Inter** (sans, nav/cuerpo/botones), vía `next/font/google`. Antes era Fraunces, pero al usuario no le gustaba la forma de la "f" (ver más abajo).
- Colores: crema/arena, negro carbón, terracota de acento, sin rojo/amarillo "Spain".
- Repo local: `/Users/evamartin/Desktop/automatizza/pauella` — **todavía sin `git init`**.
- **Fotos/vídeos originales sin procesar** (los que vas subiendo tú) viven en `source-photos/` en la raíz, excluido de git vía `.gitignore`. Las versiones optimizadas que realmente usa la web están en `public/images/` y `public/videos/`.

## Hecho

- **Home completa (una sola página, secciones ancla)**: Hero → Concept → Experience (5 pasos) → Paellas (5 platos reales) → Events (4 tipos) → About Pau → Gallery → Service Area → FAQ → Contact.
- **Hero**: replica el mockup del usuario casi al pixel (nav 3 columnas, wordmark, subtítulo tracked, CTA pill, indicador de scroll). De momento foto estática con Ken Burns sutil (ver nota sobre el vídeo más abajo).
- **Contenido real**: extraído de la web antigua (pauella.com) vía fetch — 5 paellas, tipos de evento, bio de Pau, contacto, wine upgrade. Nada inventado: sin testimonios, precios ni ciudades de cobertura no confirmadas.
- **SEO base**: metadata + OG + Twitter cards, canonical, `sitemap.ts`, `robots.ts`, JSON-LD `CateringBusiness` (con menú de paellas) + `FAQPage`, favicon generado.
- **Responsive**: verificado en 390 / 820 / 1024 / 1440px con capturas reales (Playwright). Se corrigieron 2 bugs encontrados así: el nav se rompía en tablet (breakpoint md→lg) y Pau quedaba fuera de encuadre en el hero en móvil (`object-position` responsive).
- **Formulario de contacto**: campos mínimos (Name/Email/Phone/Date/Location/Guests/Type/Message), pega a `/api/contact` (stub que solo valida y hace `console.log`, **no envía email real todavía**).
- **Selector de idioma EN/ES**: toggle arriba a la derecha, cambia todo el copy client-side, se recuerda en localStorage. Todas las secciones traducidas a mano. El JSON-LD se mantiene siempre en inglés (idioma canónico de la única URL que existe).
- `npm run build` y `npm run lint` pasan limpios en cada iteración.
- **Header más espaciado**: el nav usaba el mismo ancho que el body (max-w-7xl) sin gap entre columnas, así que en español (texto más largo) quedaba pegado al logo. Ahora el header tiene su propio ancho más generoso y un gap mínimo garantizado alrededor del logo — probado en 1280/1440/1920px en ambos idiomas.

Mismo font-family, sin cargar fuentes nuevas.

Causa: WebKit a veces ignora `font-weight` cuando ya hay `font-variation-settings` con otros ejes, si no se incluye también `'wght'` dentro del mismo string. Arreglado y verificado renderizando con el motor WebKit en local.
